# Audit Log Interceptor Sample

This sample demonstrates how a service interceptor logs activity on REST-based GIS services published through ArcGIS Enterprise or a stand-alone ArcGIS Server. Examples of service types mentioned in the sample documentation include `MapServer`, `FeatureServer`, and `ImageServer`.

The interceptor records information about incoming requests, including the requesting username, service name, service type, and operation performed on the service.

> **Version note:** The linked online sample documentation currently lists ArcGIS Enterprise SDK 12.1 on Windows and Linux. Confirm compatibility and test the interceptor packages against the target SDK and ArcGIS Enterprise build before publishing them as 12.2 samples.

## Prerequisites

- An ArcGIS Enterprise deployment or a stand-alone ArcGIS Server with a REST service available for testing.
- Administrator access to the ArcGIS Server Administrator Directory.
- The [Audit Log Interceptor sample](https://github.com/Esri/arcgis-enterprise-sdk-resources/tree/master/Samples/service-interceptors/AuditLogInterceptor).

This sample does not require a specific dataset; any supported REST-based service can be used to generate a test request.

## Download the sample code

Download the [Audit Log Interceptor sample](https://github.com/Esri/arcgis-enterprise-sdk-resources/tree/master/Samples/service-interceptors/AuditLogInterceptor) and extract it to a local directory.

The sample guide uses the compiled package:

```text
AuditLogInterceptor/target/AuditLogInterceptor.interceptor
```

If the package is not included with the downloaded sample, build the sample project before continuing.

## Deploy the interceptor

Deployment involves uploading the `.interceptor` package and registering it with ArcGIS Server.

### Upload and register

1. Sign in to the **ArcGIS Server Administrator Directory** as an administrator.
2. Navigate to **Home > uploads > upload**.
3. Click **Choose File** and select `AuditLogInterceptor.interceptor` from the `AuditLogInterceptor/target` directory.
4. Click **Upload**. On the uploaded item page, copy the **Item ID**.
5. Navigate to **Home > system > interceptors**:

   ```text
   https://<server-domain>/<server-web-adaptor>/admin/system/interceptors
   ```

6. Click **register** and paste the uploaded **Item ID** into the registration input field.
7. Click **Register** to complete registration.

According to the sample documentation, the interceptor begins processing matching requests immediately after registration.

## Verify the results

1. In the **ArcGIS Server Administrator Directory**, navigate to **Home > logs > settings > edit**.
2. Set **Log Level** to `INFO`. Leave the other settings at their defaults and save.
3. Open the ArcGIS Server REST Services Directory:

   ```text
   https://<server-domain>/<server-web-adaptor>/rest/services
   ```

4. Open a service and perform an operation, such as a query, to generate a request.
5. In the ArcGIS Server Administrator Directory, navigate to **Home > logs > query**.
6. Set **Level** to `INFO`, leave the other settings at their defaults, and click **Query**.
7. Inspect the returned logs for an entry generated by the interceptor.

### Expected result

An audit log entry generated by this sample should have:

| Log property | Expected value |
| --- | --- |
| Level | `INFO` |
| Target | `Enterprise Interceptor` |
| Message | Identifies the username, service and service type, and operation performed. |

The sample guide illustrates a log message with the following pattern:

```text
User XXXX accessed the service service name.service type.Performed the operation - operation name;
```

Actual values depend on the account, service, and operation used in your test.

> **Note:** The log contains identifiers for people accessing services. Review your organization's logging and retention practices before using this approach beyond a controlled test environment. Restore your original log level after testing if it was changed only for this sample.
